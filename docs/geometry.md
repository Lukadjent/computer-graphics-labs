# Геометрія та перетворення текстурних координат CGW

## Масштабування навколо опорної точки

CGW створена від PA3. Усі наведені нижче правила геометрії, UV-шва, нормалей, TBN та освітлення збережені. Нова операція виконується після інтерполяції uv перед трьома texture2D у фрагментному шейдері:

```text
q = uv
c = TexturePivot
S = diag(TextureScale.x, TextureScale.y)
q′ = c + S(q − c) = q + (S − I)(q − c)
st = q′ * TextureRepeat
```

Друга тотожна форма дає точну тотожність при S=I та незмінну вибірку q′(c)=c. Без останнього перенесення c масштабування виконувалося б навколо початку координат. Для c=(0.25,0.5), q=(0.4,0.7), S=(2,0.5), repeat=(1,1) отримуємо st=(0.55,0.6).

Коефіцієнти від 0.25 до 4 додатні, тому напрями нормованих T/B у базисі PA3 зберігаються. Усі три карти використовують одну фазу та масштаб. Normal map залишається картою орієнтацій PA3; її xy не перераховуються з нової карти висот. Це масштабування декоративного матеріалу, без displacement mapping.

Зміна c або S оновлює uniforms і допоміжний маркер, не викликає Model.BufferData. s опорної точки циклічно нормується в [0,1), t обмежується [0,1]. Клавіші обробляються через KeyboardEvent.code, тому не залежать від мовної розкладки. Поля INPUT, TEXTAREA, SELECT, редагований текст і системні комбінації не перехоплюються.

Маркер малюється окремим gl.POINTS у P(2πc.s, vMin+c.t(vMax−vMin)). Круглий диск формується через gl_PointCoord. Для нього вимикається перевірка глибини, тому точка помітна навіть на дальньому боці; це допоміжна позначка, а не зміна поверхні.

Періодичність геометрії не означає періодичності довільно масштабованого зображення. Різниця st.x між s=0 та s=1 дорівнює repeatU*scaleU. Для безшовного циклічного матеріалу вона має бути цілим числом. UV не затискаються і не обробляються fract у шейдері: обгортання виконує sampler REPEAT, зберігаючи коректні похідні для mipmaps.

Незалежний GPU-приклад використовує 8 × 8 RGBA-текстуру, де texel(x,y)=(30x,30y,80,255), та NEAREST. У точці c отримано (60,120,80,255) як для S=(1,1), так і для S=(3,0.25); для наведеного вище st=(0.55,0.6) отримано (120,120,80,255). Окремий приклад із від’ємними st підтвердив REPEAT: (120,150,80,255).

## Спадкування PA2

Поверхня та її параметри не змінилися:

```text
r = a + b sin(nu)
P = (r cos(u) − v sin(u), r sin(u) + v cos(u), b cos(nu))
```

Спочатку створюється замкнена сітка PA2: nu × (nv+1) спільних вершин. У кожній комірці два трикутники (a,b,c), (b,d,c), останній стовпець за u посилається на перший. Нормаль вершини обчислюється як normalize(Σ ((B−A) × (C−A))). Довжина доданка дорівнює подвоєній площі грані, тому збережено Facet Area Weighted Average варіанта 13. Вектори граней до підсумовування не нормалізуються.

## Розріз UV-шва

Після розрахунку нормалей рядки копіюються в (nu+1) × (nv+1) GPU-вершин. Остання вершина кожного рядка має ті самі позицію, нормаль і дотичну, що й перша, але s=1 замість s=0:

```text
s = i / nu
t = j / nv
index(i,j) = j*(nu+1)+i
triangles = (a,b,c), (b,d,c)
b=a+1, c=a+(nu+1), d=c+1
```

Це дозволяє інтерполювати s уздовж останньої комірки від (nu−1)/nu до 1. Без копій GPU інтерполював би до 0 через усю текстуру. Нормалі розраховуються до розрізу, тому фізично замкнений шов залишається гладким.

| Масив | Тип | Компонент на вершину |
| --- | --- | --- |
| positions | Float32Array | 3 |
| normals | Float32Array | 3 |
| tangents | Float32Array | 3 |
| texCoords | Float32Array | 2 |
| indices / wireIndices | Uint16Array | Індекси трикутників / пар U/V-ребер |

За 96 × 20 маємо 2037 вершин, 3840 трикутників, 11520 індексів. Найбільша сітка 256 × 80 має 20817 вершин — індекси вміщуються в Uint16 без розширень WebGL.

## Аналітична дотична

Зростанню s відповідає зростання u, тому дотична задається похідною:

```text
r' = b*n*cos(nu)
Pu = ((r'−v) cos(u) − r sin(u),
      (r'−v) sin(u) + r cos(u),
      −b*n*sin(nu))
Pv = (−sin(u), cos(u), 0)
```

На CPU зберігається normalize(Pu). Для сингулярної точки Pu=0 обирається скінченний напрямок, перпендикулярний до нормалі PA2. Якщо сума граней також вироджена, для N використовується (0,0,1). У такій точці однозначного геометричного базису немає; запасні напрямки запобігають NaN.

## Gram–Schmidt: варіант 13, пріоритет T

У вершинному шейдері N перетворюється оберненою транспонованою NormalMatrix, T — лінійною частиною ModelView. У застосунку ModelView задає обертання. Обидва вектори інтерполюються разом з позицією та UV. У **фрагментному** шейдері:

```text
T = normalize(tangentEye)
Nperp = normalEye − T*dot(normalEye,T)
N = normalize(Nperp)
B = normalize(cross(N,T))
```

Напрямок T збережений, змінюється N. Саме це означає пріоритет дотичної. Якщо Nperp майже нульовий, використовується проєкція безпечної координатної осі на площину, перпендикулярну T. За узгодженого обходу Pu × Pv і UV, що зростають за u/v, B орієнтований у бік +v; знак базису додатний. Віддзеркалені UV у цій параметризації не використовуються.

## Три карти

Власний матеріал генерується tools/generate-textures.cjs. Кожна карта — RGB PNG 512 × 512. Геометричні фаски та штрихи всіх карт збігаються. Функція висот h(s,t) періодична; normal map утворюється центральними різницями з циклічним продовженням:

```text
n = normalize(−dh/ds, −dh/dt, 1)
RGB = 0.5*n + 0.5
```

Шейдер декодує RGB назад у [−1,1], масштабує xy параметром сили та нормалізує. Нормаль у координатах спостерігача:

```text
Npixel = normalize(mat3(T,B,N) * normalize(decodedNormal))
```

Нормалі не зміщують вершини. Силует і кількість трикутників від сили рельєфу не змінюються. Для зворотного боку інвертується вся Npixel.

Карти завантажуються в texture units 0/1/2, кожна має свій sampler2D. Вбудовані data URL є точними копіями PNG і обходять обмеження file:// на завантаження локального зображення в WebGL. Перетворення колірного простору під час завантаження вимкнене; RGB трактуються як числові коефіцієнти. Рядок 0 відповідає v=0, UNPACK_FLIP_Y_WEBGL=false; +Y normal map спрямований уздовж +v.

Розмір 512 — степінь двійки: у WebGL 1 дозволені REPEAT, LINEAR_MIPMAP_LINEAR та generateMipmap. Цілі повтори за u зберігають періодичність шва. Нормалі після фільтрації знову нормалізуються у шейдері.

## Освітлення

З PA2 збережено Phong у координатах спостерігача:

```text
L = normalize(LightEye − PositionEye)
V = (0,0,1)                         // ортографічна проєкція
D = max(dot(Npixel,L),0)
S = D>0 ? max(dot(reflect(−L,Npixel),V),0)^Shininess : 0
I = 0.20*baseColor*AmbientEnabled
  + 0.88*diffuseTexture*D*DiffuseEnabled
  + 0.85*specularTexture*(1,0.94,0.82)*S*SpecularEnabled
```

Diffuse map впливає лише на diffuse, specular map — лише на specular. Кожна карта має окремий перемикач. Якщо normal map вимкнено або сила 0, використовується N ортогоналізованого базису. Режими показу карт виводять їх RGB без освітлення й не залежать від перемикачів матеріалу.

Одне джерело рухається по колу в світових координатах; позиція перед uniform множиться на ModelView. Обертання камери, світла та налаштування текстур змінюють лише uniforms. Геометрія перебудовується при зміні форми чи щільності сітки.

## Перевірка реалізації

node tools/check.cjs перевіряє фізичну суміжність після зварювання UV-копій, однакові N/T на шві, відсутність UV-стрибків усередині трикутників, одиничні вектори, крайні сітки та відповідність Pu незалежній чисельній похідній.

Браузерний контрольний приклад використовує той самий шейдер із T=(1,0,1), N=(0,0,1), напрямком світла (−1,0,1), лише diffuse та білим матеріалом. При пріоритеті T ортогоналізована N збігається зі світлом: вихідний канал дорівнює 0.88*255 ≈ 224. При пріоритеті N було б приблизно 159. Фактично отримано (224,224,224,255).
