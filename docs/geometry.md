# Геометрія та структура даних

## Параметризація поверхні

Ruled Rotor Cylindroid задається рівняннями:

```text
x(u,v) = (a + b sin(nu)) cos(u) - v sin(u)
y(u,v) = (a + b sin(nu)) sin(u) + v cos(u)
z(u,v) = b cos(nu)
0 <= u <= 2*pi
```

Джерело: S. N. Krivoshapko, V. N. Ivanov. *Encyclopedia of Analytical Surfaces*. Springer, 2015, с. 80 (109-та сторінка PDF).

Параметр `u` є кутовим і вимірюється в радіанах. Параметр `v` визначає положення вздовж прямолінійної твірної. Значення `a` задає сталу частину виразу `a + b*sin(n*u)`, `b` - амплітуду, `n` - частоту коливань. У програмі використовуються цілі `n`, тому кінці інтервалу `u = 0` та `u = 2π` збігаються.

За фіксованого `u` рівняння мають вигляд:

```text
P(u,v) = C(u) + v * D(u)
C(u) = ((a+b*sin(n*u))*cos(u), (a+b*sin(n*u))*sin(u), b*cos(n*u))
D(u) = (-sin(u), cos(u), 0)
```

Отже, зміна `v` задає пряму з напрямком `D(u)`, паралельну площині xOy. Для відображення вибирається скінченний діапазон `v`.

## Дві сім’ї поліліній

- **U-криві:** `v` зафіксовано, `u` змінюється від 0 до 2π.
- **V-прямі:** `u` зафіксовано, `v` змінюється від `vMin` до `vMax`.

Функція `surfacePoint` у `Model.js` обчислює координати точки за параметрами `u`, `v`, `a`, `b`, `n`. Функція `createSurfaceGeometry` формує обидві сім’ї.

Для U-кривих зовнішній цикл вибирає `v`, а внутрішній перебирає `u`. Кінцеву точку `u = 2π` включено для замикання кривої. Для V-прямих зовнішній цикл вибирає `u`, а внутрішній перебирає `v`. Пряма при `u = 2π` не додається повторно, оскільки вона збігається з прямою при `u = 0`.

## Масиви вершин

Координати зберігаються у двох плоских типізованих масивах `Float32Array`:

```text
uVertices = [x0, y0, z0, x1, y1, z1, ...]
vVertices = [x0, y0, z0, x1, y1, z1, ...]
```

На одну вершину припадають три 32-бітні числа. Координати вершини з номером `k` розташовані за індексами `3*k`, `3*k+1`, `3*k+2`.

У кожному масиві полілінії записані послідовно. Їхні межі задають масиви `uRanges` та `vRanges`:

```js
[
    { first: 0, count: 97 },
    { first: 97, count: 97 },
    { first: 194, count: 97 }
]
```

`first` є номером початкової вершини, а `count` - кількістю вершин полілінії. Обидва значення вимірюються у вершинах. Позиція `offset` у масиві координат вимірюється в числах, тому `first = offset / 3`.

За стандартних налаштувань `uSegments = 96`, `vSegments = 20`:

| Сім’я | Кількість ліній | Вершин у лінії | Усього вершин |
| --- | ---: | ---: | ---: |
| U | 21 | 97 | 2037 |
| V | 96 | 21 | 2016 |
| Усього | 117 | | 4053 |

Загальний обсяг координат у двох GPU-буферах становить `4053 * 3 * 4 = 48636` байтів. Копії координат також зберігаються в JavaScript-масивах. Точки перетину сімей повторюються в обох масивах; індексний буфер не використовується.

## GPU-буфери та малювання

Об’єкт `Model` створює два GPU-буфери: `uBuffer` і `vBuffer`. Метод `BufferData` завантажує відповідні масиви через `gl.bufferData` з підказкою `gl.STATIC_DRAW`. Геометрія оновлюється після зміни параметрів поверхні або щільності сітки.

Метод `Draw` вибирає буфер сім’ї та задає атрибут позиції:

```js
gl.vertexAttribPointer(shader.iAttribVertex, 3, gl.FLOAT, false, 0, 0);
```

Три послідовні `float` утворюють одну позицію; додаткових полів між вершинами немає. Для кожної полілінії виконується окремий виклик:

```js
gl.drawArrays(gl.LINE_STRIP, first, count);
```

Режим `LINE_STRIP` послідовно з’єднує сусідні вершини. Окремі виклики не створюють перемичок між різними полілініями. U-криві мають бірюзовий колір, V-прямі - пісочний.

## Перетворення та камера

`main.js` створює WebGL-контекст і шейдерну програму, налаштовує ортографічну проєкцію та обробляє керування. Вершинний шейдер множить координати на матрицю `ModelViewProjectionMatrix`. Під час обертання або масштабування змінюється матриця перетворення, а координати вершин залишаються сталими.

Обертання реалізує `TrackballRotator`, матричні операції - бібліотека `m4` з навчального каркаса. Програма малює лише лінії, без заповнених граней; проміжки між лініями каркаса залишаються прозорими.
